# Pig City on the Mac App Store

There are **two separate Mac builds**:

| | Local dev app | Mac App Store app |
|---|---|---|
| Name / bundle id | Pig City Dev · `com.lexiloughlin.pigcity.dev` | Pig City · `com.lexiloughlin.pigcity` |
| Config | `build/electron-builder.dev.yml` | `build/electron-builder.mas.template.yml` → generated by `scripts/prepare-mas.js` |
| Electron | regular macOS build | Electron's **MAS** build (`mas` platform) |
| Sandbox | no | **App Sandbox** on, with only the entitlements it needs |
| Signing | ad-hoc (`-`), or your Apple Development cert | Apple Distribution + Mac Installer Distribution, with a provisioning profile |
| Output | `.dmg` + `.zip` in `dist/dev/` | `.pkg` in `dist/mas/` (and a test `mas-dev` app) |
| Updates | rebuild it yourself | **only through the App Store** (no auto-updater in either build) |

Both builds bundle the game (`index.html`) and every asset (`assets/fonts/…`) inside the app. Neither one needs the internet.

## ✅ Already done (no Apple account needed)

- **Electron shell** (`electron/main.js`, `electron/preload.js`):
  - **Game files:** the game is served from `app://pig-city/` out of the app bundle. Only `index.html` and `assets/` can be loaded.
  - **Network:** the page's security policy and the app's main process both refuse any internet connection.
  - **Page lockdown:** the game page runs sandboxed and isolated. It has no Node access, can't open new windows or navigate away, and gets no camera, mic or location.
  - **Saves:** the town is saved to `Saves/town.json` in the app's data folder, plus `town.backup.json` refreshed every 10 minutes. Files are written then renamed, so a crash can't leave half a file. The game also saves when the window closes.
  - **Export/Import:** **File ▸ Export Town… (⌘E)** and **Import Town… (⌘O)** use the system save/open panels. In the sandbox those panels are what grant access to the file the player picks.
  - **Menu and window:** a standard Mac menu (Pig City, File, Edit, View ▸ Big Map / Full Screen, Window, Help ▸ How to Play). Closing the window quits the game.
- **Game fixes for the app:**
  - **Fonts:** bundled locally instead of loaded from Google Fonts.
  - **Dialogs:** `prompt()` doesn't exist in Electron, so all naming and confirm boxes are now in-game dialogs.
  - **Export/import in the browser too:** the web version gets 💾 Export town / 📂 Import town as well, as a download and a file picker.
- **Entitlements:**
  - **`build/entitlements.mas.template.plist`:** `app-sandbox`, `application-groups` (`<TEAMID>.com.lexiloughlin.pigcity`, which Electron needs) and `files.user-selected.read-write` (export/import). That's all. No network, camera, mic or temporary exceptions.
  - **`build/entitlements.mas.inherit.plist`:** the helper processes inherit the sandbox.
  - **`build/entitlements.mas.loginhelper.plist`:** sandboxes Electron's login helper.
- **Info.plist:** `ElectronTeamID` (filled in from your Team ID), the Games › Simulation category, `ITSAppUsesNonExemptEncryption = false` (no export-compliance paperwork), macOS 12+, and Retina support.
- **Icon:** `build/icon.png` (1024×1024). electron-builder turns it into `icon.icns`.
- **Scripts:**
  - `npm run audit:sandbox` runs 28 sandbox-compatibility checks (see `docs/SANDBOX_AUDIT.md`).
  - `scripts/prepare-mas.js` fills in your Team ID and checks your provisioning profile (team, bundle id, expiry, dev vs. distribution) and your certificates.
  - `npm run verify:mas` inspects a finished store build: sandbox, signature, embedded profile, Team ID and installer signature.
- **Privacy policy page:** `privacy.html`, which will be at https://lexiloughlin.github.io/pig-city/privacy.html. The App Store requires one.
- **Optional CI:** the GitHub Actions workflow "Mac dev build" builds the dev `.dmg` on a GitHub Mac. It **only runs when you start it** and uploads nothing to Apple.
- **Tested** (Linux test runs, since the final builds need a Mac):
  - The app loads, bundled fonts work, and the page has no Node access.
  - Save files are written, and the game saves on close.
  - Export and import work, both from the buttons and from the File menu, and a bad file is rejected.
  - Internet requests and navigation are blocked, and only `index.html` and `assets/` are served.
  - The dev and MAS configs package correctly: the right files go into `app.asar`, the Info.plist values are correct, and the MAS build pulls Electron's `mas` binary.

## 1. Run and build the local dev app (on your Mac)

You need **Node.js 20 or newer** (nodejs.org) and **Xcode Command Line Tools** (`xcode-select --install`).

```bash
git clone https://github.com/lexiloughlin/pig-city.git
cd pig-city
npm install
npm start            # runs the game in a window, with Reload / DevTools in the View menu
npm run pack:dev     # → dist/dev/mac-arm64/Pig City Dev.app (mac/ on Intel Macs), quick, for testing
npm run dist:dev     # → dist/dev/Pig City Dev-1.0.0-universal.dmg
```

The dev app is ad-hoc signed and built on your own Mac, so it opens normally. If you copy it to another Mac, right-click ▸ **Open** the first time.
Its town lives in `~/Library/Application Support/Pig City/Saves/`.

## 2. What still needs your Apple account

These steps need you, because they use your Apple ID, money or legal agreements.

### A. Join the Apple Developer Program
1. Go to https://developer.apple.com/programs/enroll/ and enroll as an Individual. It's $99 a year.
2. In App Store Connect, go to **Business** and accept the **Paid Apps agreement**, plus tax and banking if you'll charge for the game. The free-apps agreement is accepted automatically.
3. Find your **Team ID** (10 characters) under developer.apple.com ▸ Account ▸ Membership details.

### B. Register the app id
1. Go to developer.apple.com ▸ Certificates, IDs & Profiles ▸ **Identifiers** ▸ **+** ▸ App IDs ▸ App.
2. Choose **macOS**, then Explicit Bundle ID **`com.lexiloughlin.pigcity`**, with description "Pig City".
3. You don't need to tick any extra capabilities. The app group name starts with your Team ID, which macOS allows without registering it.

> If you want a different bundle id, change it in `build/electron-builder.mas.template.yml`, `build/entitlements.mas.template.plist` and `scripts/prepare-mas.js` (`BUNDLE_ID`).

### C. Certificates (they go into your Mac's keychain)
The easiest way: open Xcode ▸ Settings ▸ Accounts, add your Apple ID, then **Manage Certificates ▸ +** and create:
- **Apple Distribution** (signs the App Store app)
- **Mac Installer Distribution** (signs the `.pkg`; it shows in Keychain as "3rd Party Mac Developer Installer")
- **Apple Development** (only for the sandboxed test build)

### D. Provisioning profiles (Profiles ▸ +)
1. **Mac App Store Connect** (distribution): pick App ID `com.lexiloughlin.pigcity` and your Apple Distribution certificate. Download it and save it as **`build/embedded.provisionprofile`**.
2. *(Optional, to test the sandbox)* First register this Mac under **Devices**. You'll need its Provisioning UDID, from  ▸ About This Mac ▸ More Info ▸ System Report. Then create a **macOS App Development** profile for the same App ID and save it as **`build/dev.provisionprofile`**.

These files are git-ignored, so they never go into the repo.

### E. Tell the build your Team ID
Either create `build/mas.local.json` (git-ignored):
```json
{ "teamId": "ABCDE12345" }
```
or prefix commands with `APPLE_TEAM_ID=ABCDE12345`.

### F. Test the sandboxed build on your Mac (optional, recommended)
```bash
npm run dist:mas-dev
open dist/mas-dev/*/"Pig City.app"
```
Things to check:
- In Activity Monitor ▸ View ▸ Columns, turn on **Sandbox**. Pig City should say "Yes".
- Play, quit and reopen: your town should still be there. It's saved in `~/Library/Containers/com.lexiloughlin.pigcity/Data/Library/Application Support/Pig City/Saves/town.json`.
- Try ⌘E (Export) to your Desktop and ⌘O (Import) back in.

### G. Build the App Store package
```bash
npm run dist:mas        # runs the sandbox audit, checks your profile and certificates, then builds
npm run verify:mas      # double-checks signature, sandbox, profile and installer signature
```
The result is a `.pkg` in `dist/mas/` (e.g. `Pig City-1.0.0-universal.pkg`).

### H. Create the app in App Store Connect
1. Go to https://appstoreconnect.apple.com ▸ Apps ▸ **+ New App**.
2. Fill in:
   - **Platform:** macOS.
   - **Name:** "Pig City". It has to be unique on the store, so have a backup ready, like "Pig City: Guinea Pig Town".
   - **Primary language:** English (U.S.).
   - **Bundle ID:** `com.lexiloughlin.pigcity`.
   - **SKU:** anything, e.g. `pigcity-mac-1`.
3. Fill in the store listing:
   - **Category:** Games ▸ Simulation, with Casual as an optional second category.
   - **Price:** Free, or a price tier.
   - **App Privacy:** choose **"Data Not Collected"**. The app has no network access, analytics or accounts.
   - **Privacy Policy URL:** `https://lexiloughlin.github.io/pig-city/privacy.html`
   - **Support URL:** e.g. `https://lexiloughlin.github.io/pig-city/` or the GitHub repo.
   - **Age rating questionnaire:** answer honestly. A cozy town builder with no violence or chat is usually 4+. Don't pick the Kids category unless you want its extra rules.
   - **Screenshots:** 1 to 10 at 16:10, e.g. 2880×1800 or 1440×900. In the app, use ⌘⇧4 then Space to capture the window. Make sure the shots don't show the "Dev" build name.
   - **Also needed:** a description, keywords, a promotional text (optional) and the copyright line "2026 Lexi Loughlin".

### I. Upload and submit (when you're ready; nothing here has been done)
1. Install **Transporter** from the Mac App Store, sign in, and drag in the `.pkg` from `dist/mas/` ▸ **Deliver**.
2. After processing (about 10 to 60 minutes), the build appears in App Store Connect. You can try it with **TestFlight** first.
3. Select the build on the version page, then **Add for Review** ▸ **Submit**.

## Updating the store version later

The App Store version updates only through the App Store. Players get new versions automatically from the App Store app; there's no updater inside the game.

1. Make your changes to the game (`index.html`). The website and both Mac apps share the same file.
2. Bump `"version"` in `package.json`, e.g. `1.0.1`. That becomes the version players see.
3. Every upload also needs a higher **build number**:
   ```bash
   npm run dist:mas -- -c.buildVersion=2
   ```
4. `npm run verify:mas`, upload with Transporter, create the new version in App Store Connect, and submit.

Every so often, also update Electron (`npm install --save-dev --save-exact electron@<newer>`) to pick up security fixes, then re-test.

## Moving a town between versions

The website, the dev app and the store app each keep their own save. To move a town, use **💾 Export town** in one and **📂 Import town** in the other.

## Troubleshooting

- **`prepare-mas` lists ✗ problems:** it tells you exactly what's missing (Team ID, profile, certificate).
- **"No identity found":** if you have several certificates, choose one with
  `CSC_NAME="Lexi Loughlin (ABCDE12345)" npm run dist:mas`.
- **The app opens then quits right away in the sandbox build:** usually the Team ID in the profile doesn't match `ElectronTeamID` or the application group. Re-run `npm run prepare:mas` and rebuild.
- **App Review mentions private APIs:** make sure the build came from `dist:mas`. It uses Electron's MAS build, which removes them.
